# 2D Configuration (`settings_2D.htm`, subpage 10)

Source: WLED 17.0.0-dev. Paths relative to `wled00/`. Page: `data/settings_2D.htm`. Loader: `xml.cpp:724-754`. Saver: `set.cpp:863-893`. JSON: `cfg.cpp:192-222` (read), `cfg.cpp:968-985` (write). Compiled out entirely with `WLED_DISABLE_2D` (menu button hidden, `xml.cpp:213-215`; route removed, `wled_server.cpp:763-765`).

## What it configures

A 2D matrix built from 1..`WLED_MAX_PANELS` (18, `const.h:190`) rectangular LED panels. Each panel has its own size, position (offset) inside the virtual matrix, wiring start corner, orientation and serpentine flag. From these the firmware builds a mapping table (`setUpMatrix()`, `FX_2Dfcn.cpp:21`) that converts logical (x,y) to physical LED index. The panels are laid onto the existing LED buses in physical order; the page does not touch bus config.

## Page lifecycle

1. `S()` loads `/settings/s.js?p=10`, then `UI()` and sets `MPC.max = maxPanels` (`settings_2D.htm:21-28`).
2. `s.js?p=10` (`xml.cpp:724-754`):
   - `d.Sf.SOMP.value = isMatrix`
   - `maxPanels=18; resetPanels();`
   - if matrix: `PW`/`PH` set to panel 0's size (generator convenience), `MPC` = panel count, then for each panel `addPanel(i)` and `P{i}B/R/V/S/X/Y/W/H` values.
   - with `WLED_DISABLE_2D`, removes the "2D Matrix" option instead.
3. `UI()` (`settings_2D.htm:30-38`): if `SOMP=0`, hide everything and reset panels; otherwise show and `draw()`.
4. Save uses `fS()` → `d.Sf.submit()` (buttons are `type=button`, so there is no submit handler or validation) (`settings_2D.htm:11`, `255`, `309`).

## Fields

### Mode

| Field | Label | Values | `set.cpp` | cfg.json |
|---|---|---|---|---|
| `SOMP` | Strip or panel | 0 1D Strip, 1 2D Matrix | `strip.isMatrix = toInt` (`:866`) | presence of `hw.led.matrix` |

Changing `SOMP` in the UI calls `resetPanels(); addPanels(); UI();` which leaves one default panel.

### Panel set-up

| Field | Label | Range | `set.cpp` | cfg.json |
|---|---|---|---|---|
| `MPC` | Number of panels | 1..`maxPanels` (HTML says 64, JS caps to 18) | `constrain(MPC, 1, WLED_MAX_PANELS)` (`:869`) | `hw.led.matrix.mpc` |

Editing `MPC` adds or removes panel rows at the end (`addPanels()`, `settings_2D.htm:40-45`). New rows default to generator `PW`×`PH` size, offset 0,0.

### Per-panel fields (`addPanel`, `settings_2D.htm:47-70`)

Names are `P{i}X` with decimal `i` (P0B, P1B, …, P17B).

| Field | Label | Values / range | Server type (`FX.h:1016-1037`) | `set.cpp:873-886` | cfg.json `hw.led.matrix.panels[]` |
|---|---|---|---|---|---|
| `P{i}B` | 1st LED (vertical) | 0 Top, 1 Bottom | bit `bottomStart` | `toInt` | `b` |
| `P{i}R` | 1st LED (horizontal) | 0 Left, 1 Right | bit `rightStart` | `toInt` | `r` |
| `P{i}V` | Orientation | 0 Horizontal, 1 Vertical | bit `vertical` | `toInt` | `v` |
| `P{i}S` | Serpentine | checkbox | bit `serpentine` | `hasArg` | `s` |
| `P{i}W` | Dimensions W | 1-255 | `uint8_t width` | `toInt` | `w` |
| `P{i}H` | Dimensions H | 1-255 | `uint8_t height` | `toInt` | `h` |
| `P{i}X` | Offset X (LEDs from top-left) | 0-255 (HTML); server `uint16_t` | `xOffset` | `toInt` | `x` |
| `P{i}Y` | Offset Y | 0-255 (HTML); server `uint16_t` | `yOffset` | `toInt` | `y` |

The server loop stops at the first missing `P{i}B` (`set.cpp:877`), so `MPC` larger than the number of submitted panels is harmless.

### Matrix generator (client-side only)

Collapsible "Matrix Generator" section (`settings_2D.htm:267-287`). Its fields are submitted with the form but the server ignores them (`PW`/`PH` are only re-emitted by `s.js` as a convenience).

| Field | Label | Range |
|---|---|---|
| `PW` | Panel dimensions W | 1-128, default 8 |
| `PH` | Panel dimensions H | 1-128, default 8 |
| `MPH` | Horizontal panels | 1-8 |
| `MPV` | Vertical panels | 1-8 |
| `PB` | 1st panel vertical | 0 Top, 1 Bottom |
| `PR` | 1st panel horizontal | 0 Left, 1 Right |
| `PV` | Orientation (panel chain direction) | 0 Horizontal, 1 Vertical |
| `PS` | Serpentine (panel chain) | checkbox |

"Populate" runs `gen()` (`settings_2D.htm:90-120`):

- Sets `MPC = MPH × MPV` and creates that many panels, all `PW × PH`.
- Iterates the panel grid in chain order. `h`/`v` are the grid dimensions swapped if the chain is vertical. Panel `p` gets grid coordinates `(x, y)`, flipped by `PR`/`PB` (swapped roles when vertical), with alternate rows reversed if `PS`.
- Sets `P{p}X = x × PW`, `P{p}Y = y × PH` (or swapped when vertical).
- Only offsets and sizes are generated. Each panel's own start corner, orientation and serpentine stay at defaults (Top, Left, Horizontal, not serpentine); the page warns the user may need to edit each panel.

Generator bug: the guard is `if (j*i < maxPanels) addPanel(p)` instead of `p < maxPanels`. With more than 18 panels (e.g. 5×4), later iterations reference non-existent `P{p}X` inputs and throw. The `MPH`/`MPV` inputs allow up to 8×8 = 64.

### Preview canvas (`draw()`, `settings_2D.htm:128-248`)

Draws the virtual matrix bounding box (yellow), each panel outline (white), the wiring path (start dot green, end dot red, serpentine or raster lines), and panel number. Below it: "Matrix Dimensions (W*H=LC): W x H = N" where W/H are max(offset + size) across panels. Canvas width 640 px (400 on narrow windows); height scales with aspect ratio.

### Gap file

"Gap file" upload (`settings_2D.htm:302-306`) posts the chosen file to `/upload` as `/2d-gaps.json` (`uploadFile` in `common.js:171-191`; PIN-protected). Format: JSON array with one entry per matrix cell (row-major over W×H): `-1` = no LED at this position (not counted), `0` = LED present but never lit, `1` = normal. Read by `setUpMatrix()` (`FX_2Dfcn.cpp:65-101`); a file shorter than W×H is ignored. It only takes effect on the next matrix rebuild (2D save, bus re-init, or reboot).

## Server apply (`set.cpp:863-893`)

1. `strip.isMatrix = SOMP`; `strip.panel.clear()`.
2. If matrix, read up to `MPC` panels.
3. `strip.suspend(); strip.waitForIt();` → `strip.deserializeMap()` → `strip.makeAutoSegments(true)` → `strip.resume()`.
4. Config is saved in the next loop. No reboot.

`deserializeMap(0)` (`FX_fcn.cpp:2253-2271`): if `/ledmap.json` exists, it is used instead of the panel layout (and can itself set width/height and force matrix mode). Only if no `ledmap.json` exists and `isMatrix` is set does it call `setUpMatrix()`.

`setUpMatrix()` validation (`FX_2Dfcn.cpp:24-47`): matrix width = max(xOffset+width), height = max(yOffset+height). If W×H > `MAX_LEDS`, W > 255, H > 255, W ≤ 1 or H ≤ 1, it logs "2D Bounds error", **sets `isMatrix=false`, clears panels and resets segments**. The page does not pre-validate any of this; a bad layout silently reverts the device to 1D. A 1×N or N×1 matrix is rejected.

`makeAutoSegments(true)` force-recreates segments, so saving this page discards the user's segment layout.

## JSON path

- Read: `hw.led.matrix` exists only when `isMatrix` (`cfg.cpp:968-985`): `{mpc, panels:[{b,r,v,s,x,y,h,w}]}`. Live matrix size is in `/json/info` → `leds.matrix.{w,h}` (`json.cpp:733-739`).
- Write: `POST /json/cfg` with `hw.led.matrix` sets `isMatrix=true` and replaces panels (`cfg.cpp:194-221`), but does not call `setUpMatrix()`/`deserializeMap()`; the layout applies on next bus re-init or reboot.
- There is no JSON way to turn matrix mode off.

## Replacement notes

MVP scope: the PRD does not list 2D. The Visual Segment Designer (§13) needs to know whether the device is 2D and its W×H, which is read-only from `/json/info` `leds.matrix`. Recommend: show matrix dimensions read-only; link to the stock `/settings/2D` page for editing.

If 2D editing is added later:

- Use form POST to `/settings/2D` (full field set: `SOMP`, `MPC`, all `P{i}*`), since it applies immediately and can disable 2D. JSON writes need a reboot or bus re-init to take effect.
- Validate client-side what the firmware enforces silently: W, H in 2..255, W×H ≤ `MAX_LEDS`, panel count ≤ 18, and ideally Σ panel LEDs ≤ total LED count.
- Warn that saving recreates segments.
- Detect `ledmap.json` (via `/json/info` `maps` containing id 0, or `/edit?list`) and warn that it overrides panel layout.
- Reimplement the generator correctly (cap by panel index, optionally apply per-panel start/orientation/serpentine too) and a wiring preview; the stock one is the main usability gain available here.
