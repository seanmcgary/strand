# LED & Hardware settings (`settings_leds.htm`, subpage 2)

Source: WLED 17.0.0-dev. Paths relative to `wled00/`. Page: `data/settings_leds.htm`. Loader: `xml.cpp:336-470`. Saver: `set.cpp:176-427`. JSON equivalents: `cfg.cpp:175-563` (read) and `cfg.cpp:956-1081` (write).

## Page lifecycle

1. `S()` (`settings_leds.htm:39-60`):
   - restores "Show Advanced Settings" from `localStorage.ASc`;
   - fetches `/json/info` to set `hasPSRAM` from `psrSz`/`psram` (only used for HUB75 validation);
   - `loadJS('/settings/s.js?p=2')` with a pre-hook that resets `d.ledTypes`, `d.um_p`, `d.rsvd`, `d.ro_gpio`, `d.max_gpio`, and a post-hook that runs `checkSi()`, `setABL()`, attaches `trySubmit` to submit, drops the `-1` placeholder from `d.um_p`, then `fetchPinInfo(pinDropdowns)` (loads `/json/pins` and converts GPIO number inputs to dropdowns).
2. `s.js?p=2` (`xml.cpp:336-470`) emits, in order: GPIO info, `d.ledTypes=[...]`, `bLimits(...)`, global flags, one `addLEDs(1)` plus field assignments per existing bus, `MA/ABL/PPL`, `resetCOM(n)` + `addCOM(...)` per override, defaults, relay, `addBtn(i,pin,type)` per button, `IP`, `TT`, `IR`, `IT`, `MSO`.
3. `UI()` (`settings_leds.htm:283-522`) runs on almost every input change and recomputes visibility, limits, start indices, memory, power and channel usage.
4. Submit → `trySubmit()` (`settings_leds.htm:137-170`) validates, then `d.Sf.submit()` POSTs to `/settings/leds`.

Bus field names use a suffix character for the bus index: `0-9` then `A-Z` (`chrID()`, `settings_leds.htm:28`), max 36 buses in UI and server (`settings_leds.htm:540`, `set.cpp:218`).

## LED type list (`d.ledTypes`)

Generated by `BusManager::getLEDTypesJSONString()` (`bus_manager.cpp:1346-1370`) as a JS array of `{i, c, t, n}`:

- `i`: type id (`const.h:340-393`)
- `c`: capability bitmask: `0x01` RGB, `0x02` white channel, `0x04` CCT, `0x10` 16-bit, `0x20` off-refresh mandatory (`bus_manager.cpp:1349`, `bus_manager.h:176-199`)
- `t`: pin-layout code; the UI derives behavior from it (`settings_leds.htm:14-27`):
  - `"D"` single-wire digital (1 GPIO)
  - `"2P"` two-wire digital (data + clock GPIO)
  - `"A"`…`"AAAAA"` PWM, one GPIO per `A`
  - `""` On/Off relay output (1 GPIO), counted as analog by `isAna`
  - `"N"` network bus (4 fields = IPv4 octets)
  - `"V"` virtual (not currently emitted)
  - `"H"` HUB75 matrix (5 config fields, not GPIOs)
- `n`: display name

ABL logic (UI):

- `setABL()` on load ticks `ABL` if global `MA>0` or any per-bus `MA{n}>0`, sets each `LAsel{n}` to the matching preset, else "Custom" (`settings_leds.htm:216-242`).
- `enPPL()` (`settings_leds.htm:185-206`): with PPL, global `MA` becomes read-only and equals the sum of per-bus `MA{n}`; per-bus `MA{n}` min 250 for digital buses. Without PPL, per-bus `MA{n}` is recomputed as `round(MA * count / totalDigitalCount)` (display only; the server zeroes per-bus max when PPL is absent).
- On submit, if `!ABL || PPL` the global `MA` is sent as 0 (`settings_leds.htm:164`).
- Runtime (`bus_manager.cpp:1542-1581`): if global max > 0, one brightness scale is applied across all digital buses (buses with LED mA 0 are skipped). If global max is 0, each bus limits itself against its own max. PWM, On/Off and network buses never participate.

Power estimate shown on the page (`settings_leds.htm:497-510`): `busMA = Σ(LA{n} × LC{n})` over digital buses, with `LA=255` counted as 12 mA. "Brightest white" PSU = `ceil((100+busMA)/500)/2` A (rounded up to an integer above 5 A); "most effects" = `ceil((100+busMA)/1500)/2` A. A safety warning appears when `MA > 7200`.

## Bus list mechanics

- `addLEDs(1)` appends a row (`settings_leds.htm:533-626`): fills the type select from `d.ledTypes`, sets `LS` to the previous bus's end (`lastEnd`, PWM counts as 1), defaults length 1 and mA preset 55, then picks the first non-disabled type after `updateTypeDropdowns()`.
- `addLEDs(-1)` removes the last row. `+` hidden at 36 buses, `-` hidden at 0.
- Start indices: when custom starts are off, `UI()` overwrites each `LS` with the running total and disables the field (`settings_leds.htm:398-399`). `startsDirty[]` tracks manually edited starts.
- Total LED count shown = max(start+len); "physical" count excludes network buses (`settings_leds.htm:400-411`, `487-488`).

### Type availability (`updateTypeDropdowns`, `settings_leds.htm:924-1001`)

Run twice per `UI()`. Per bus dropdown:

- If the bus is not digital and digital buses ≥ `maxD`, all `D` options are disabled.
- ESP32: if RMT is full and an I2S bus exists, non-digital buses may only switch to the same digital type as the first I2S bus.
- An I2S bus that is not the first I2S bus may only use the first I2S bus's type (parallel I2S requires identical type).
- 2-pin types are limited to 2 buses.
- PWM types are disabled when they need more pins than `maxA - usedPWMpins` (plus this bus's own pins).
- Driver dropdown: I2S disabled when I2S is full; RMT disabled when RMT is full; overflowing buses are flipped to the other driver.

### Channel usage (`getDuse`, `settings_leds.htm:890-921`)

ESP32 family only. Counts RMT vs I2S digital non-2P buses. Shown as "Hardware channels used: RMT x/maxRMT, I2S y/maxI2S", red when over (`settings_leds.htm:472-481`). `isBCok()` (`settings_leds.htm:272-281`) flags a bus invalid if its I2S type differs from the first I2S type or either channel pool is over capacity.

### Memory estimate (`getMem`, `settings_leds.htm:244-269`)

Per bus:

- PWM / On-Off: 5 B.
- Otherwise `len = LC + SL`; pixel buffers `pbfr = len × 8`; channels `ch = 3·RGB + W + CCT`; `mul = 1`.
- Digital: 16-bit types double `len`. ESP8266 on GPIO3 (DMA) `mul = 5`. ESP32 non-2P: `mul = 2` for RMT; for I2S `mul = 1` plus a share of the DMA buffer: `maxLEDs × ch × (24 if parallel/S3 else 3) / i2sCount`.
- Total `= len × ch × mul + dma + pbfr`.

Sum vs `maxM` gives `bquot` %. Bar is grey < 60%, orange 60-90%, red > 90%. Warning "You might run into stability or lag issues" when any digital bus > min(maxPB, 800) LEDs or `bquot > 80`. Submit is blocked above 100%; above 80% the user gets "reboot recommended". The firmware repeats the check at init and replaces over-budget buses with placeholders, raising `ERR_NORAM` (`FX_fcn.cpp:1373-1393`).

## GPIO dropdowns and conflict checks

- `pinDropdowns()` (`settings_leds.htm:824-851`) converts number inputs into `<select class="pin">` via `makePinSelect(name, flags)` (`data/common.js:306-356`). Flags: 1 = output required, 2 = touch, 4 = ADC. LED pins and relay use 1, IR uses 0, buttons use 0/2/4 by type.
- Options list -1 ("unused") then all GPIOs except `d.rsvd`, filtered by flags. Pins allocated on the device (from `/json/pins`) are disabled and labelled with the owner name, except the field's own current value. A saved pin that is no longer valid is shown with "⚠".
- `pinUpd()` (`settings_leds.htm:852-888`) cross-updates all selects so a pin chosen in one is disabled (labelled "LED" or the field name) in the others.
- Virtual and HUB75 buses revert to plain number inputs (`unmakePinSelect`).
- `pinsOK()` on submit (`settings_leds.htm:79-136`): every required pin of non-virtual, non-HUB75 buses must be set; a pin must not be in `d.rsvd`, `d.um_p`, or used by a button/IR/relay select; must not be input-only; must not duplicate another LED pin. Failure alerts and blocks submit.

## Submit validation (`trySubmit`, `settings_leds.htm:137-170`)

1. `pinsOK()`.
2. `isBCok()` for every bus → "Invalid Bus-config".
3. HUB75: panels must equal rows × cols; height ≥ 64 with > 1 panel requires PSRAM; ESP32-S3 alerts "HUB75 changes require a reboot".
4. Memory > 100% blocks; > 80% warns.
5. If `!ABL || PPL`, `MA=0`.
6. HTML5 `checkValidity()`, re-enable type selects, submit.

## Server apply sequence (`set.cpp:176-427`)

1. Deallocate relay, IR and button pins (`:180-197`).
2. Set global ABL max, auto-segments, CCT flags, blend, global AW mode, FPS.
3. Loop bus index 0..35 while `L0{n}` exists and `LC{n} > 0`; build `BusConfig` entries into `busConfigs`.
4. Rebuild color-order map.
5. Reallocate IR, relay, buttons with type-specific validation (ESP32 checks ADC/touch capability).
6. Defaults, gamma (rebuild LUT), transition, palettes, nightlight, palette blend, brightness factor.
7. `doInitBusses = busesChanged`. The next `loop()` recreates buses, realigns or fixes segments, restores brightness, then writes `/cfg.json` (`wled.cpp:239-254`). No reboot.

## Config template import (`loadCfg`, `settings_leds.htm:742-823`)

Reads a local `cfg.json`-format file and fills the form (does not save): replaces all buses from `hw.led.ins` (pins, type, drv, start, len, order nibbles, skip, ref, rev, rgbwm, freq, ledma, maxpwr), global `hw.led.maxpwr`, color-order overrides from `hw.com`, buttons from `hw.btn.ins` and `tt`, IR, relay, `light.aseg`. Note it writes the raw `freq` into the `SP` select, which expects an index 0-4.

## Replacement notes

MVP (PRD §17): one or more LED outputs with type, GPIO, LED count, color order, reverse; brightness/current limit "if exposed cleanly". Proposed MVP field set:

- Per output: `type`, `pin[]` (with type-aware pin count), `len`, `start` (auto-computed by default), `order` low nibble, `rev`. Show `skip` and W-swap if cheap.
- Current limiting: global ABL on/off + PSU mA (`hw.led.maxpwr`), per-output mA/LED (`ledma`) with the five presets. Treat per-output limiter (PPL) as advanced.
- Defaults: boot on, boot brightness, boot preset. These are commonly touched and trivial.
- Brightness factor (`BF`) and gamma can be included cheaply.

Leave to the stock UI: network/HUB75 buses, driver (RMT/I2S) selection, clock speed, off-refresh, color-order overrides, auto-white/CCT options, buttons, IR, relay, touch threshold, transitions, random palette, timed light defaults, palette wrapping, FPS, config template import.

Gotchas:

- Capability data (type list, `bLimits`, reserved/input-only/touch/ADC pins) is only in `s.js?p=2` (and partly `/json/pins`). Without it the replacement cannot reproduce type filtering or pin validation. Either parse `s.js` or ship a per-version table and use `/json/pins` + `info.arch`.
- The replacement must re-implement at least: required-pin check, duplicate/reserved/input-only pin rejection, digital bus count vs `maxD`, per-bus LED max (`maxPB`), and the memory estimate. The firmware silently drops or placeholders invalid buses rather than returning an error.
- ESP32 parallel I2S requires all I2S buses to share one LED type.
- Saving buses re-creates all outputs and may realign segments; warn that segments can change.
- If writing via form POST, all fields must be sent; missing `IR`/`RL` allocate GPIO0.
- If writing via `/json/cfg`, include `fps` and `rgbwm` in `hw.led`, and full `light.gc`, or they reset.
- Starts: when the user does not customise starts, compute them cumulatively; via JSON you must send explicit `start` values.
- `freq` units differ between form (index) and JSON (Hz/kHz).
- Relay "Invert" is inverted relative to `cfg.json` `rev`.
- ABL only affects digital buses; hide current fields for PWM/On-Off/network.
- `info.leds.pwr` / `info.leds.maxpwr` give live current estimate for display.
