# DMX Output Settings (`settings_dmx.htm`, `dmxmap.htm`)

Both pages exist only in builds with `WLED_ENABLE_DMX` (not in default release builds). Without it, `/settings/dmx` falls through to the settings menu (`wled00/wled_server.cpp:759-761`), the menu's DMX button stays hidden (`wled00/xml.cpp:216-218`), `/dmxmap` is not registered (`wled_server.cpp:619-621`), and `handleSettingsSet` has no DMX branch (`wled00/set.cpp:695-723`). DMX output drives a wired DMX512 line (fixed GPIO 2, reserved in `xml.cpp:126-130`) by mapping each LED to a fixture.

DMX *input* (E1.31/Art-Net over the network, and wired DMX input) is on the Sync page; see `sync-interfaces.md`.

## `settings_dmx.htm`

Loaded at `/settings/dmx`, values from `GET /settings/s.js?p=7` (`xml.cpp:678-703`), saved via `POST /settings/dmx` → `set.cpp:696-722`. Heading: "Imma firin ma lazer (if it has DMX support)". Help button opens `https://kno.wled.ge/interfaces/dmx-output/`.

Load: `GCH(15)` builds 15 channel selects before s.js runs; `mMap()` runs after to grey out unused channels and show the overlap warning (`settings_dmx.htm:43-46`).

| Label | Field | Type / range | Conditional | set.cpp | cfg.json |
|---|---|---|---|---|---|
| Proxy Universe ... from E1.31 to DMX (0=disabled) | `PU` | number 0-63999, required (`settings_dmx.htm:58`) | — | `set.cpp:698-699` → `e131ProxyUniverse`. When non-zero, received E1.31 data on that universe is passed straight to DMX out, and LED→DMX output below is disabled. | `dmx.e131proxy` |

| DMX fixtures start LED | `SL` | number 0-1500 in HTML (`:67`) | — | `set.cpp:713-716` (0..MAX_LEDS-1) → `DMXStartLED` | `dmx.start-led` |

Number of fixtures = total LED count from the LED page ("Number of fixtures is taken from LED config page").

All values apply live (used by the DMX output loop); no reboot. Save response "DMX settings saved."

Note: field name `CS` collides in meaning with `CS` (countdown seconds) on the Time page and `CS{i}` (SSID) on the WiFi page. Each page posts to its own subpage so there is no runtime conflict.

## `dmxmap.htm`

`GET /dmxmap` (`wled_server.cpp:619-621`). Read-only visualization of all 512 DMX channels. The build step `tools/cdata.js:429-439` injects the template placeholder `%DMXVARS%` into `FM()`; at request time `dmxProcessor` substitutes `CN`, `CS`, `CG`, `LC` (total LED count), and `CH[]` (the 15-entry fixture map) (`wled_server.cpp:150-169`). The placeholder does not appear in the source HTML.

`FM()` (`dmxmap.htm:4-22`) marks every channel DISABLED, then for each LED `i` sets channels `CS + CG*i + j` (j < CN) to the function in `CH[j]`, and renders 512 boxes labelled SET 0 / RED / GREEN / BLUE / WHITE / SHUTTER / SET 255 / DISABLED, color-coded. No form fields. It does not bounds-check: LED counts that push past channel 512 write beyond the array silently.

## Replacement notes

Not in PRD MVP (§16-§20 do not mention DMX; §19 explicitly defers advanced realtime protocols). DMX output is a non-default compile option, so most target devices will not have it. Use the §21 escape hatch.

If ever supported: detect availability by the presence of the `dmx` object in `/json/cfg` (only serialized with `WLED_ENABLE_DMX`, `cfg.cpp:1262-1274`). The map page is a pure function of `chan`, `start`, `gap`, `fixmap` and LED count and can be re-rendered client-side.
